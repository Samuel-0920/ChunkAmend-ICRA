# 数据 schema 与质量检查

依据：本副本的实际保存器、控制器，以及只读核验过的 uf850_real_lemon_to_basket_v001/meta/info.json、provenance/semantics.json、首回合 Parquet。完整来源见 evidence/SCHEMA_REFERENCE.json。新任务尚无数据，以下是接口合同与验收要求，不是已通过的新数据验收。

| 内容 | 原始采集 | 派生 LeRobot v2.1 |
|---|---|---|
| 图像 | front.mp4 + wrist.mp4，640×480，名义30 fps | observation.images.front / wrist；保持两路，不替代为黑图 |
| 状态 | observation.state：SDK 关节反馈槽位(rad) + 夹爪 pulse/850 | 6关节(rad) + 夹爪，共7维 |
| 动作 | action：最近SDK接受的绝对关节目标(rad) + 实际取整的夹爪命令/850 | 同一语义的7维绝对目标，不是下一帧状态 |
| 时间 | sample_monotonic_s、frame_index、timing_json | timestamp=frame_index/30 对应名义视频时间；原主机时间另存 provenance |
| 成功 | termination_reason 与 task_success 分开；B结束不是自动成功 | 人工按本任务条件审核后入选 |

旧柠檬数据八槽到七维的映射是 [0,1,2,3,4,5,7]。SDK 第七关节槽位（索引6）在旧数据全为零；新数据仍须逐回合验证真实宽度、有限值、索引6为零和有效轴语义。遇到非零或维度变化停止转换并查 SDK/记录来源，不能删列凑维度。夹爪0为闭合、1为名义张开；反馈轻微超过1应原样保留并报告，不静默裁剪。

实际采样与两路相机读操作分别有主机时间、相机序号、SDK提交/返回时间。它们不是曝光时间，不声称硬件同步。保持动作/图像帧对应，不删中间帧以隐藏重复或延迟。SDK返回0代表接受，不等于目标已经执行到位。

采集保存器已有：双路/向量/时序校验、临时目录写入、视频解码检查、哈希、fsync和完整回合提交。审核已有：原件哈希、manifest/review快照核验及失败时清空候选清单。audit_bundle.py 能输出原始哈希、采样时钟、重复相机序号与主机读取年龄；它不是完整训练数据验收器。

转换验收还需：逐视频完整解码与帧数一致、维度与单位核验、命令时间先于样本且SDK返回成功、真实采样时序与过期检查、任务文本一致、审核与成功来源一致、源视频复制哈希相同、实际固定版本LeRobot loader读入和回合边界检查。旧转换器的50 ms采样间隔及250 ms观测年龄阈值是原工程筛查设置，不是硬件同步标准。

后续 OpenPI 训练沿用已核验适配语义：H15，整个片段的前6维减同一个当前状态，夹爪保持绝对值；推理加回同一状态一次。RGB、前置/腕部键与对应适配器保持一致。LeRobot版本不能随意升级到v3后仅改版本字符串。本轮不加载模型、不训练、不计算或复制旧任务 norm_stats。
